## 2. 背景与目标

OpsPaw 目标是在不绕过 JumpServer 的前提下，提供企业可控的 AI 运维能力：

- 提供内部运维 Web 应用
- 提供标准外部 API 调用能力
- 保证 JumpServer 为唯一事实源
- 支持通过 JumpServer API 初始化和持续同步数据库

## 3. 产品定位与边界

### 3.1 核心定位

- `JumpServer`：权限控制、远程执行、审计事实源
- `OpsPaw`：编排、策略、审批、展示、集成、聚合查询

### 3.2 AI 在 MVP 的角色

- AI 仅用于诊断建议与执行计划建议
- AI 不直接生成并落地自由命令
- 进入执行链路的命令必须来自模板白名单
- AI 建议的模板变更必须经人工审核后发布

### 3.3 低风险修复边界（MVP 强制）

允许：

- 服务状态检查、端口检查、日志采样、健康检查
- 无状态服务重启（模板化）
- 临时目录白名单清理（模板化）

禁止：

- 任意 `rm`、磁盘分区变更、权限体系变更
- 数据库 DDL/DML 写操作
- 网络策略和防火墙批量修改
- 任意自由命令执行

### 3.4 渐进式自治路径

OpsPaw 不应一开始追求“全自动闭环”，而应采用四阶段信任阶梯：

- `Observe`：只读观察与建议，不执行
- `Shadow`：给出计划并模拟执行链路，不触发真实动作
- `Guarded`：仅执行白名单低风险动作
- `Closed-loop`：在少数成熟场景开启闭环自动化

MVP 只落到 `Observe + Guarded`，并要求所有生产场景默认可退回 `Observe`。

## 4. 用户与角色

- 一线运维：发起任务、查看建议、执行低风险动作
- 值班负责人：审批高风险动作、升级和接管
- 平台管理员：维护模板、策略、同步与集成配置
- 安全审计：抽查审计链路与配置变更日志
- 外部调用方：监控、ITSM、ChatOps、自动化平台

## 5. 数据主权与系统关系

### 5.1 唯一事实源

- 资产事实：JumpServer API
- 系统用户事实：JumpServer API
- 执行事实：JumpServer `ops/command-executions`
- 审计事实：JumpServer `audits/...`

### 5.2 OpsPaw 本地库定位

- 投影缓存（projection）
- 编排状态
- 查询聚合与报表
- 审计关联索引

禁止本地“反向覆盖”JumpServer 主数据。

### 5.3 与 CMDB 关系

- CMDB 与 JumpServer可能并存
- MVP 约束：执行权限与可执行资产以 JumpServer 为准
- CMDB 仅作为补充业务属性来源（如业务线、负责人）
- 若 CMDB 与 JumpServer 冲突，执行层以 JumpServer 为最终判定

## 6. 关键业务流程

### 6.1 Web 自用主流程

1. 选择场景（巡检/诊断/修复）
2. 场景路由引擎按规则匹配模板集合
3. 策略引擎评估风险
4. 低风险直接执行，高风险进入审批
5. 通过 JumpServer 执行
6. 验证引擎判定结果
7. 生成报告并归档审计链路

### 6.2 验证失败处理

- 第一次失败：按策略重试一次（仅低风险）
- 仍失败：任务标记 `failed_need_handover`
- 自动创建人工接管工单
- 人工接管后的操作需关联回原 `task_id/trace_id`

### 6.5 影子模式与演练模式

- 影子模式：完整跑通路由、策略、审批、执行计划生成，但不调用 JumpServer 执行
- 演练模式：对测试资产或沙箱资产执行真实命令，用于模板验证与策略验证
- 任何新模板、新策略、新场景上线前，必须先经过影子模式或演练模式验证

### 6.3 外部 API 主流程

1. 外部系统发起任务
2. 鉴权 + 幂等校验 + 参数校验
3. 异步创建任务并返回 `task_id`
4. 任务执行与状态回调
5. 调用方可轮询或接收回调

### 6.4 任务取消流程

- 新增接口：`POST /openapi/v1/tasks/{task_id}/cancel`
- 仅 `pending/planning/awaiting_approval` 可取消
- 已进入 JumpServer 执行阶段不可强制取消，仅可标记“停止后续动作”

## 7. 功能需求

### 7.1 Web 应用

- 首页看板：总量、成功率、耗时分布、审批通过率、JumpServer 响应时间
- 资产中心：投影数据 + 同步状态 + 删除/失效标识
- 任务中心：状态机、人工接管、失败重试
- 执行中心：脱敏日志、执行耗时、上游耗时
- 审批中心：超时升级、转交机制
- 策略模板中心：黑白名单、模板审核、二次确认
- 集成配置中心：连接检查、同步策略、告警阈值
- 配置审计页面：谁在何时改了策略/模板/集成配置
- 证据卡页面：展示“为什么建议执行这个动作”的证据、来源、置信度
- 数据新鲜度标识：展示资产、系统用户、执行状态的最近同步时间
- 影子模式控制台：查看建议动作、模拟结果、未通过策略原因

### 7.2 外部 API

- 任务创建、查询、取消
- 审计摘要查询（按时间/资产/调用方聚合）
- 回调重试策略：指数退避，最多 8 次，失败入死信队列
- 幂等窗口：24 小时
- 支持调用方传入 `trace_id`，平台透传并补全链路
- 支持任务去重键：相同告警源、相同资产、相同时间窗内自动折叠任务

## 8. 数据同步与初始化

### 8.1 初始化（JumpServer -> OpsPaw）

- 任务：`jms_bootstrap_init`
- 执行顺序：
  1. 拉取资产分页数据
  2. 按资产拉取系统用户映射
  3. upsert 投影表
  4. 记录快照（count + checksum）
  5. 触发一致性校验任务

### 8.2 增量同步双轨策略

- 策略 A：时间戳/游标增量（若 JumpServer 能力稳定）
- 策略 B：全量比对增量（小规模或上游游标不稳定时启用）

### 8.2.1 数据血缘与新鲜度

- 所有投影数据必须记录 `source_id`、`source_type`、`sync_at`、`snapshot_version`
- Web 与 API 在返回投影数据时必须附带 `freshness_status`
- 当数据超过阈值未同步时，平台应主动降级为“只读建议，不允许执行”

### 8.3 删除与失效规则

- 资产不在上游出现：标记 `inactive`
- 连续 N 次（默认 3 次）同步缺失后允许物理归档
- 映射解除不物理删除，标记失效并保留历史关联

### 8.4 唯一键与约束

- `asset_projection.jms_asset_id` 唯一
- `system_user_projection.jms_system_user_id` 唯一
- `asset_system_user_map(jms_asset_id,jms_system_user_id)` 复合唯一
- `execution.jms_execution_id` 唯一
- `audit_link.jms_audit_relation_id` 唯一

### 8.5 初始化与同步性能约束

- 拉取采用分页 + 并发受控
- 默认并发：资产分页 4，系统用户拉取 16（可配置）
- 触发上游限流时自动退避

## 9. 非功能与运行策略

### 9.1 非功能性假设与降级

- JumpServer 可用：正常执行
- JumpServer 部分不可用：停止执行，允许读取本地缓存并标记“可能过期”
- JumpServer 全不可用：停止执行与审批落地，保留查询历史与告警能力

### 9.2 安全与合规

- 脱敏责任在 OpsPaw 后端统一处理
- 敏感字段规则：正则 + 关键字字典双策略
- 高风险动作无 bypass 接口
- 模板发布需管理员二次确认
- 所有日志、终端输出、工单内容、监控告警文案都视为“不可信输入”
- LLM 上下文构造阶段必须隔离不可信文本，防止日志中的提示注入

### 9.2.1 高级安全风险

- `Prompt Injection`：攻击者通过日志/主机名/告警内容诱导模型越权
- `Data Poisoning`：低质量历史案例污染建议质量
- `Callback SSRF`：恶意回调地址导致内网探测或凭据泄露
- `Replay Attack`：重复提交旧请求或旧回调造成状态错乱
- `Audit Tampering`：中间层日志缺失导致审计链断裂

应对要求：

- 回调地址白名单
- 幂等签名 + 时间戳校验
- 案例知识库人工审核与质量评分
- 审计链双写：业务表 + 结构化操作日志

### 9.3 稳定性

- 任务超时、重试、熔断
- 回调死信队列
- 健康探针：30s 一次，连续 3 次失败告警
- 队列堆积告警与任务背压
- 任务去重与合并，避免告警风暴造成任务雪崩
- 执行预算控制：单任务可操作主机数、最大并发数、最大持续时间

### 9.4 性能目标（MVP）

- Web 首屏 P95 <= 2s
- 任务创建 API P95 <= 800ms
- 100 并发创建任务，P95 <= 1.5s
- 1000 资产初始化 <= 10 分钟

## 10. 验收标准

### 10.1 功能验收

- Web 全流程可用：任务、审批、执行、审计、配置审计
- 外部 API 可用：创建、查询、取消、审计摘要
- 初始化、增量同步、降级策略可验证

### 10.2 数据验收

- 唯一键冲突数 = 0
- 主数据一致率 >= 99.9%
- 一致率定义：`核心字段一致资产数 / JumpServer 资产总数`
- 核心字段：`hostname/ip/env/status`

### 10.3 审计验收

- 审计链路完整率 100%
- 完整定义：`task_id/execution_id/jms_execution_id/trace_id` 可反查
- 支持回溯 JumpServer 原始执行与审计记录

### 10.4 安全验收

- 敏感信息泄露事件 = 0
- 通过静态扫描 + 日志脱敏测试 + 红线命令拦截测试

### 10.5 可靠性验收

- JumpServer 超时故障演练可触发降级与告警
- 回调失败可进入重试并最终落死信

### 10.6 自治与可解释性验收

- 新模板上线前必须完成一次影子模式验证记录
- 低风险执行动作必须附带证据卡与置信度说明
- 单任务的执行范围、预算、审批链可在 UI 上完整回溯

## 11. 里程碑计划（修订）

### Phase 1（3 周）

- JumpServer 初始化同步链路 + 一致性校验
- Web：看板、资产中心、任务中心
- OpenAPI：任务创建与状态查询

### Phase 2（4 周）

- 审批中心、策略模板中心、配置审计页面
- API：任务取消、审计摘要、回调重试机制
- 增量同步双轨策略
- 影子模式、证据卡、数据新鲜度标识

### Phase 3（4 周+）

- 扩展场景与 Skill
- 多 JumpServer source 支持
- 审计报表与运营指标完善
- 任务去重、执行预算、告警风暴抑制
- 闭环自动化场景灰度发布

## 12. 风险与应对

- JumpServer 接口变化：采用 Adapter + 契约测试 + 版本支持矩阵
- AI 幻觉风险：模板化执行 + 人工审核发布
- 审批绕过风险：统一审批引擎，无 bypass
- 大规模同步性能风险：并发可配 + 分片任务 + 全量比对兜底
- 日志提示注入风险：不可信输入隔离 + 上下文清洗
- 数据过期误判风险：新鲜度展示 + 超时禁止执行
- 告警风暴风险：任务折叠 + 背压 + 执行预算
- 回调与幂等竞态风险：签名校验 + 幂等表 + 状态机保护

## 13. 运维手册交付要求

必须交付：

- 同步失败排查与重跑手册
- 策略错误回滚手册
- 审计导出操作手册
- JumpServer 不可用应急手册
