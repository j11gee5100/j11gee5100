# 交付包类型设计：首装包 / 升级包 / 覆盖包

## 纠偏结论

首装 / 升级 / 覆盖是**交付包**的类型，不是环境包小资产的类型。

环境包资产仍然保持通用：上传包文件、适配配置、前置检查脚本、安装脚本、验证脚本、依赖、安装顺序。

## 类型定义

| 类型 | 字段值 | 使用场景 |
| --- | --- | --- |
| 首装包 | `first_install` | 某设备适配历史的第一次完整部署包 |
| 升级包 | `upgrade` | 已有环境上的模型、运行时或配置增量升级交付包 |
| 覆盖包 | `overwrite` | 面向新装/重装服务器的最终一体交付包；当设备历史已有首装包和升级包后，可沉淀为覆盖包 |

## 示例

以 `A10 推理服务器 01` 为例：

1. 最开始适配该设备，生成一个首装交付包。
2. 后续模型升级，生成一个升级交付包。
3. 如果新装一台同型号/同适配配置服务器，不必先安装首装包再安装升级包，而是生成一个最终覆盖交付包。

## 当前实现

- `delivery_bundle.bundle_type` 保存交付包类型。
- `manifest.json` 顶层输出 `bundle_type`。
- 环境包资产接口不再输出 `install_stage` / `replaces_package_ids`。
- 交付包页面和交付包编辑页提供“交付类型”选择。
