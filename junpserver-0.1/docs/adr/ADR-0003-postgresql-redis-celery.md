# ADR-0003: 主数据库、缓存与任务执行采用 PostgreSQL + Redis + Celery

- 状态：Accepted
- 日期：2026-04-02

## 背景

OpsPaw 的核心数据具备明显关系性：

- 任务
- 执行
- 审批
- 审计关联
- 主数据投影
- 幂等记录

同时系统需要：

- 异步任务执行
- 定时同步
- 回调重试
- 分布式锁和短期缓存

## 决策

采用：

- `PostgreSQL` 作为主数据库
- `Redis` 作为缓存、队列辅助和分布式锁基础设施
- `Celery` 作为 MVP 阶段的后台任务执行框架

## 备选方案

- MongoDB 作为主库
- Kafka/RabbitMQ 作为主任务队列
- Temporal 作为工作流引擎

## 选择理由

- PostgreSQL 更适合强关系、唯一键、事务一致性
- Redis 对 MVP 足够轻量，适合限流、缓存、任务辅助
- Celery 在 Python 生态中成熟，足以支撑同步、回调、编排任务

## 暂不选择 Temporal 的原因

- 引入成本更高
- 当前团队更需要先验证状态机与上游契约
- MVP 阶段工作流复杂度还未达到必须上 Temporal 的程度

## 结果

优点：

- 成熟稳健
- 开发与运维成本较低
- 便于快速形成可运行闭环

代价：

- 长链路编排需要我们自己设计状态机
- 当工作流进一步复杂时，后续可能要重评估 Temporal
