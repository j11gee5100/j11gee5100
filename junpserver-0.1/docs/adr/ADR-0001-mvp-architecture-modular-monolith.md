# ADR-0001: MVP 采用模块化单体 + 独立 Worker

- 状态：Accepted
- 日期：2026-04-02

## 背景

OpsPaw 的 MVP 需要在较短周期内实现以下闭环：

- JumpServer 主数据同步
- 任务编排
- 策略与审批
- 受控执行
- 审计关联
- Web 和 OpenAPI 访问

团队规模有限，且当前主要复杂度在状态机、幂等、风控和审计一致性，而不是超大规模服务治理。

## 决策

MVP 采用：

- 一个模块化单体 `ops-api`
- 多个独立 Worker 进程
- 清晰的模块边界，而不是一开始拆成大量微服务

推荐运行单元：

- `ops-api`
- `orchestrator-worker`
- `sync-worker`
- `callback-worker`
- `scheduler`

## 备选方案

- 重微服务
- 单进程全堆在一个服务内

## 选择理由

相比重微服务：

- 更适合当前团队规模
- 部署、联调、排障更简单
- 可以先把关键闭环跑稳

相比单进程全堆：

- Worker 与 API 分离后，任务和同步链路更稳定
- 更利于后续按热点拆分

## 结果

优点：

- 实施速度快
- 复杂度可控
- 后续有演进空间

代价：

- 代码组织要求更严格
- 必须在仓库内部维持清晰边界，防止“伪单体大泥球”
