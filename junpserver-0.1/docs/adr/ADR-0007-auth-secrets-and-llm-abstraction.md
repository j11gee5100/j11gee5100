# ADR-0007: 认证、密钥与 LLM 集成采用统一抽象层

- 状态：Accepted
- 日期：2026-04-02

## 背景

OpsPaw 同时面向：

- Web 用户
- 外部 API 调用方
- JumpServer 集成凭据
- LLM 服务调用

这些能力都涉及身份、凭据、审计和后续替换成本。

## 决策

采用如下策略：

- Web 认证：企业 SSO / OIDC 优先
- 外部 API：MVP 先 Access Token，增强阶段支持 HMAC + 时间戳
- JumpServer 凭据：统一进入 Secret Manager / Vault
- LLM：通过内部 `llm-provider` 抽象层接入，不在业务代码中直接耦合具体厂商 SDK

## 备选方案

- 在应用配置文件中保存 JumpServer 凭据
- 直接在业务代码中绑定单一模型 SDK
- 外部 API 从一开始就只做复杂签名体系

## 选择理由

- 凭据管理必须统一，才能满足安全和审计要求
- LLM 供应商、合规要求、配额策略未来都可能变化
- Web 和 API 的认证需求不同，应该分层处理

## 结果

优点：

- 安全边界更清晰
- 后续替换模型和凭据策略更容易
- 更符合企业环境治理方式

代价：

- 初期要多做一层抽象
- 集成和配置管理复杂度略高
