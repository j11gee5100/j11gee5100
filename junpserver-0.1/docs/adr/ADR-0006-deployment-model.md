# ADR-0006: 部署采用 Compose for dev，Kubernetes for test/prod

- 状态：Superseded by ADR-0008
- 日期：2026-04-02

## 背景

OpsPaw 的开发、测试、生产环境诉求不同：

- 本地开发更看重快速启动与调试
- 测试/生产更看重隔离、扩缩容、可观测和发布稳定性

## 原决策

采用：

- 本地开发：`Docker Compose`
- 测试与生产：`Kubernetes`
- 大日志和报表附件：S3/MinIO 兼容对象存储

## 备选方案

- 所有环境统一 Compose
- 所有环境统一虚拟机进程部署
- 一开始就强绑定某云厂商专有平台

## 选择理由

- Compose 对本地协作和快速启动更友好
- Kubernetes 更适合多 worker、回调、定时任务和灰度演进
- 对象存储适合放日志附件和导出报表，不挤占主库

## 结果

优点：

- 本地开发快
- 测试/生产弹性和隔离更好
- 演进空间足够

代价：

- 环境差异管理需要规范
- 需要补齐 Helm/Manifest/配置模板等运维工作

## 说明

该决策基于“测试/生产有容器平台”的假设形成。

在明确运行环境为 Linux 服务器后，本决策被 `ADR-0008` 替代：

- MVP 与试点阶段优先采用 Linux 服务器友好的部署方式
- Kubernetes 不再作为默认前提，而作为后续规模化选项
