# AI 推理环境安装包编排平台产品设计文档

## 1. 产品目标

当前产品目标是支持环境工程人员把零散推理环境安装包管理为标准资产，并通过配置化方式筛选、组合、排序、出包，最终形成可交付的大环境包。

一句话：

> 从“人工拼环境”变成“平台筛包、选包、排顺序、生成总脚本、输出大包”。

## 2. 当前 MVP 产品边界

### 2.1 平台负责

- 环境安装包资产管理。
- 安装包适配条件管理。
- 安装包依赖/冲突管理。
- 按目标环境筛选可用包。
- 环境组合 recipe 管理。
- 安装顺序编排。
- 生成 manifest。
- 生成总安装脚本。
- 生成环境 bundle 构建记录。

### 2.2 平台暂不负责

- 不负责远程自动安装。
- 不负责测试用例管理。
- 不负责总装交接完整流程。
- 不负责模型训练和模型版本生产。
- 不负责 GPU 调度和在线推理服务发布。

## 3. 导航与页面设计

一级菜单建议：`环境出包`。

页面建议分为 5 个 Tab：

1. 安装包库
2. 适配规则
3. 依赖关系
4. 组合方案
5. 构建产物

## 4. 页面设计

### 4.1 安装包库

目标：管理可复用安装包资产。

列表字段：

- 包 ID
- 包名称
- 包类型
- 版本
- 文件 URI
- checksum
- 是否 root
- 是否重启
- 是否离线
- 状态
- 更新时间

核心操作：

- 新增安装包。
- 编辑安装包。
- 上传/登记文件 URI。
- 配置安装脚本片段。
- 配置验证脚本。
- 启用/停用包版本。

包类型建议：

- driver
- firmware
- runtime
- framework
- python
- inference_server
- system_dependency
- model_dependency
- custom

### 4.2 适配规则

目标：声明包版本适合哪些目标环境。

筛选维度：

- 硬件厂商
- CPU 架构
- 操作系统
- 操作系统版本
- 推理卡厂商
- 推理卡型号
- 驱动版本
- CUDA/CANN/ROCm 版本
- Python 版本

核心操作：

- 给某个包版本新增适配规则。
- 编辑适配规则。
- 测试规则是否匹配某个目标环境。

### 4.3 依赖关系

目标：管理包之间的安装前后关系和冲突。

字段：

- 源包
- 目标包
- 关系类型：requires/conflicts/recommends/replaces
- 说明

核心操作：

- 新增依赖。
- 新增冲突。
- 查看某个包的依赖树。

### 4.4 组合方案

目标：按目标环境筛包、选包、排序，保存为 recipe。

页面流程：

1. 输入目标环境条件。
2. 点击“筛选可用包”。
3. 平台按包类型展示候选版本。
4. 用户选择包版本。
5. 用户拖拽或手动设置安装顺序。
6. 点击“校验依赖/冲突”。
7. 保存 recipe。
8. 点击“生成环境包”。

目标环境条件字段：

- 硬件厂商
- CPU 架构
- 操作系统
- 操作系统版本
- 推理卡厂商
- 推理卡型号
- 期望运行时
- 期望推理框架
- 期望推理服务

Recipe 列表字段：

- recipe ID
- 名称
- 版本
- 目标环境摘要
- 包数量
- 状态
- 创建人
- 更新时间

### 4.5 构建产物

目标：查看已经生成的大环境包。

列表字段：

- bundle ID
- bundle 名称
- bundle 版本
- recipe
- 构建状态
- 包文件 URI
- manifest URI
- install.sh URI
- 构建人
- 构建时间

核心操作：

- 查看 manifest。
- 下载环境包。
- 下载总脚本。
- 标记测试状态，可选。
- 复制构建配置重新出包。

## 5. 状态设计

### 5.1 安装包状态

```text
draft       草稿
active      可用
inactive    停用
deprecated  废弃
```

### 5.2 Recipe 状态

```text
draft       草稿
validated   已校验
built       已出包
archived    归档
```

### 5.3 Bundle 构建状态

```text
pending     待构建
building    构建中
success     构建成功
failed      构建失败
archived    归档
```

## 6. 关键用户故事

### 6.1 环境包维护人员

作为环境包维护人员，我希望维护每个安装包版本的适配条件、安装脚本和校验脚本，以便其他人组合环境时不再依赖口口相传。

验收标准：

- 可以创建包版本。
- 可以配置适配条件。
- 可以配置安装脚本片段。
- 可以配置依赖和冲突。

### 6.2 环境包编排人员

作为环境包编排人员，我希望输入目标硬件和系统条件后，平台自动筛选可用包版本，我只需要选择包和安装顺序，就能生成总脚本和大包。

验收标准：

- 可以输入目标条件。
- 可以看到候选包版本。
- 可以选择包。
- 可以设置顺序。
- 可以保存 recipe。
- 可以生成 bundle。

### 6.3 测试/交付人员

作为测试或交付人员，我希望拿到的环境包包含清晰 manifest 和总安装脚本，知道里面有哪些包、版本、顺序和适配条件。

验收标准：

- bundle 有 manifest。
- bundle 有总安装脚本。
- bundle 能追溯 recipe 和包版本。

## 7. MVP 原型建议

一期可以先做轻量化页面：

- 安装包库：表格 + 新增/编辑弹窗。
- 适配规则：作为安装包详情页的一部分，或独立 Tab。
- 组合方案：采用步骤条表单。
- 安装顺序：一期可用数字顺序字段，后续再做拖拽。
- 出包：一期可先生成 manifest 和 install.sh 文本，并记录 bundle；压缩打包可作为后续增强。

## 8. 后续演进

- 支持上传文件到 MinIO。
- 支持真正生成 tar.gz/zip 大包。
- 支持依赖图可视化。
- 支持规则表达式和版本范围。
- 支持脚本安全扫描和审批。
- 支持测试平台回写。
- 支持总装交付状态。
- 支持自动化远程安装。
